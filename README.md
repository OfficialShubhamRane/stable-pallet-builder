# Stable Pallet Builder

Packs a set of boxes onto a pallet and searches for the most stable arrangement,
then renders the result as an interactive 3D Plotly view.

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## Run

```bash
.venv/bin/python stable_pallet_builder.py                  # random boxes, 500 iterations, opens the 3D view
.venv/bin/python stable_pallet_builder.py --seed 7          # reproducible box set and search
.venv/bin/python stable_pallet_builder.py --no-plot         # console + pallet.json only
.venv/bin/python stable_pallet_builder.py --iterations 2000 --verbose
.venv/bin/python stable_pallet_builder.py --carton-types 3   # only 3 distinct carton sizes
.venv/bin/python stable_pallet_builder.py --packer heightmap  # the old grid heuristic
.venv/bin/python stable_pallet_builder.py --allow-tipping      # let cartons rest on any face
```

Every run prints independent checks: box overlaps, static equilibrium, and
load-bearing limits.

Output goes to the console, `pallet.json`, and a browser window with the 3D pallet.

## Box mix

Boxes are drawn from a catalog of `CARTON_TYPES` distinct carton sizes rather
than randomising every dimension independently, which is how a real warehouse
stocks cartons. Carton sides are multiples of `GRID_STEP` so each one fills
whole height-map cells. Weight follows each type's density with
`WEIGHT_JITTER` variation, so two boxes of the same carton weigh about the same.

Fewer carton types means less variability and a tighter pack: at 25 unique
shapes the same 25 boxes stack to ~53", at 5 types ~46", at 1 type ~32".

## Algorithms

Two packers are available. `--packer ep` (default) is the research-grounded one;
`--packer heightmap` keeps the original grid heuristic for comparison.

### Extreme-point packer (`ep_packer.py`, default)

1. **Candidate positions** are Extreme Points, generated by projecting the
   corners of each placed box onto the cargo and walls below it, rather than
   every cell of a discretised grid. Boxes keep their exact dimensions, so
   nothing is lost to grid rounding.
2. **Placement choice** minimises the Residual Space merit function: the slack
   left on each axis after the box goes in, plus a pallet-specific term that
   charges heavy cargo for going high.
3. **Stability** is static mechanical equilibrium, the box's centre of gravity
   must project inside the convex hull of its contact patches. This replaces
   the "75% of the base is supported" proxy: it is both more correct (a box
   supported at two opposite corners passes the area test but tips) and less
   restrictive, so it packs more.
4. **Load bearing**: each carton has a rated top load. A box's weight is split
   among its supporters by contact area and passed down the support chain;
   placements that would crush a carton are rejected.
5. **Search** is GRASP: six literature ordering rules seed it, then randomised
   construction from a restricted candidate list, then destroy-and-rebuild.

See [REFERENCES.md](REFERENCES.md) for the papers and what was left out.

### Height-map packer (`--packer heightmap`)

1. **Placement** (`build_pallet`) keeps a height map of the pallet at `GRID_STEP`
   resolution. For each box it evaluates every candidate position and both
   footprint rotations at once with a sliding window, and picks the lowest-cost
   spot. Cost combines resting height (weighted harder for heavy boxes), support
   ratio, distance from the pallet centre, and void volume trapped underneath.
   A stacked box must rest on at least `SUPPORT_THRESHOLD` of its footprint.
2. **Search** (`search_best_arrangement`) tries several ordering heuristics
   (density, weight, volume, footprint, height) and then hill-climbs by swapping
   pairs in the best order found so far. Arrangements are ranked by boxes placed
   first, then by `stability_score`.

Tune the height-map packer with `W_HEIGHT`, `W_SUPPORT`, `W_CENTER` and
`W_GAP`; tune the extreme-point packer with `EP_ITERATIONS`, `EP_WEIGHT_BIAS`
and `EP_STABILITY_MARGIN`.

## Configuration

| Constant | Meaning |
| --- | --- |
| `PALLET_WIDTH` / `PALLET_DEPTH` / `MAX_HEIGHT` | pallet envelope, inches |
| `GRID_STEP` | height-map resolution, inches |
| `SUPPORT_THRESHOLD` | height-map packer only: minimum supported fraction of a stacked box's footprint |
| `LOAD_BEARING_PSI` | lbs/sq-in a carton top can bear before crushing |
| `EP_ITERATIONS`, `EP_WEIGHT_BIAS`, `EP_STABILITY_MARGIN` | extreme-point packer tuning |
| `EP_ALLOW_TIPPING` | allow all six rotations instead of keeping cartons upright |
| `CARTON_TYPES` | distinct carton sizes in the catalog (lower = less variability) |
| `CARTON_MIN` / `CARTON_MAX` | smallest and largest carton side, inches |
| `WEIGHT_JITTER` | weight variation within a carton type (0 = identical) |
| `NUM_BOXES`, `SEARCH_ITERATIONS` | defaults for the demo run |
